# CPU OCR spike result

PP-OCRv5 mobile detector plus the eslav mobile recognizer is accepted as the RU+EN default. The production Rust path reached 2.06% normalized CER on 84 synthetic Segoe UI crops versus 1.96% for the Python/RapidOCR reference. Pure English remained suitable: the main weak cases were tiny 12 px punctuation and visually confusable Latin/Cyrillic glyphs (`O/О`, `p/р`, `x/х`). Output must not case-fold or “correct” those confusables silently.

The selected crop is never expanded. Preprocessing creates an internal 8 px replicated-edge border and uses 2× Catmull-Rom upscaling only for selections whose long edge is at most 464 px. The border removed detector misses on text touching crop edges. Official detector preprocessing is BGR, ImageNet mean/std, DB threshold 0.3, box score 0.6, unclip 1.5. Recognition resizes to height 48, zero-pads batches to at least width 320, and greedily decodes 519 CTC classes: blank index 0, 517 dictionary entries, then a literal space.

Rust uses the pure-Rust DB contour/min-area-rectangle/Clipper and perspective-crop implementation from `ppocr-rs 0.7.3` (Apache-2.0), with a local batched recognizer. Measurements below ran the optimized `cargo test --release` binary on a Ryzen 9 5900X after the final DLL-loading and crop-bounding changes. The 84 small crops measured 21.63 ms median and 56.36 ms p95. A dense 1920×1080 sample with 45 detected regions took 769.89 ms including initialization in a fresh test process. Full HD is kept in one 960-long-edge detector run; larger selections are tiled. Cancellation is checked while waiting for the shared engine, after each detector call, between recognition batches, and between tiles. A single active ONNX detector or recognizer call remains non-interruptible.

Six colored foreground/background fixtures measured 2.61% normalized CER, 26.09 ms median, and 162.17 ms p95 in the same release profile. Three were exact. The other three each exposed a Latin/Cyrillic lookalike (`x/х`, `e/е`, or `p/р`); they did not show a color-channel failure. This supports the explicit RGBA-to-BGR conversion required by the pinned Paddle detector configuration, while the small sample remains a regression check rather than proof across arbitrary colors.

The official ONNX Runtime 1.23.2 Windows x64 release is loaded by absolute path with telemetry disabled. App-local Microsoft retail CRT DLLs are copied from the licensed Visual Studio Build Tools REDIST directory, Authenticode-checked, and recorded with version/hash in the generated manifest. No Python, OpenCV, runtime network access, image logging, or text logging ships in the application.

All quality and latency numbers are synthetic; the Full-HD result is one sample rather than a distribution. The next quality gate should add consented real screenshots covering ClearType, fractional DPI scaling, translucent surfaces, and dense multi-column layouts.
